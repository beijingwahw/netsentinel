# NetSentinel V3 能力速览(README_V3)

**净网哨兵(NetSentinel)** 是一套"识别 → 复核 → 举报辅助"的本地化工具链:对运营者提供的 URL 做网页抽样与图像识别,判定疑似色情站点并生成可签名的证据包,经**人工确认**后辅助把举报信息填写到 12377(中央网信办举报中心)与扫黄打非门户。V3 的主题是**从"感知"到"智能体平台"**:GLM 从打分器升级为规划侦查的"办案侦探",识别链学会"不确定才请大模型"的级联纪律,名单质量获得带前提的统计担保,证据连成跨站点团伙网络,运营长出四眼复核、声明式政策、复核 TUI 与并发调度这些平台级骨架——而**人的最终拍板地位,三轮升级从未动摇**。

> 前置阅读:v1 手册 [USAGE.md](USAGE.md)、V2 总览 [UPGRADE_V2.md](UPGRADE_V2.md);V3 全量细节见 [UPGRADE_V3.md](UPGRADE_V3.md)。

## 八大亮点

1. **案件智能体(GLM 办案侦探)**:扫描之后,智能体阅读报告摘要(高分图、成员分歧、URL/文本风险),产出"类别假设 + 至多 5 项侦查动作 + 置信度"的严格 JSON 计划,执行复扫页面 / 复核图片 / 追加抽样,至多两轮、低置信才续。侦查结论**只升不降**——机器只补证据,永不翻案,永不替人拍板。
2. **级联路由(省着用大模型)**:flash 小模型先行,校准分落在不确定带 `[0.15, 0.85]` 内才升级大模型复核,带外高置信直接采用。每一跳独立走 30 天缓存与每日预算,离线与预算耗尽优雅降级,单图失败不拖垮整站。
3. **共形预测(95% 担保,诚实版)**:用人工核验过的校准集为"分值 ≥ 阈值"的入报名单拟合经验精度下限。担保随行前提(同分布、n≥30、含正样本),样本不足时明说"不给担保"、宁出空名单——绝不宣传无条件精度。
4. **主动学习(复核结论反哺)**:批准 / 驳回结论被收集为监督信号,产出 `nsfw_threshold` 等三项阈值**调整建议**(样本 <20 不建议)与"边缘优先"的 VLM 送审排序。只有建议权:生效须人改配置并重启。
5. **证据网络(团伙发现)**:感知哈希库识别"同一素材换站重传",站点关联图谱把共享图片 / 模板 / 重定向沉淀为带权团伙边,重定向追踪剥开短链与跳板,动图 / 视频帧采样补齐动态内容盲区。全部仅存本地,关联是线索而非扩表许可。
6. **平台治理(四眼 + 政策)**:高价值条目可要求**两名不同审核人**齐批(四眼原则,同人拦截、留痕审计);分流规则从代码搬进 `policy.yaml`(首条命中,四动作:入列 / 提醒 / 仅记录 / 四眼),任何配置组合都不能削弱人工门。
7. **运营骨架(TUI + 复核台 v2 + 池化 + 自适应)**:纯标准库复核 TUI(批准前强制"我已人工核实"确认问句)、带趋势 / 模型一致性 / 图谱 / 政策模拟 / 四眼面板的复核台 v2、并发扫描池(礼貌间隔 + 去重 + 失败隔离)、按站点波动率自适应的重扫间隔建议。
8. **信任链(签名 + 适配器 + RAG + 鲁棒性)**:证据包 manifest 支持 HMAC-SHA256 签名与篡改检出;门户表单结构外置为 yaml 适配器(验证码只许出现在人工门步骤);内置 12377 分类与法规条目标题的中文检索,给举报类别建议;对抗基准用四类扰动(模糊 / 马赛克 / 遮挡 / 低质重编码)评估识别链稳健度。

## 快速上手:三条命令

```bash
# ① 稳定层扫描(v1/v2 行为,默认全离线、stub 分类器)
python -m netsentinel --config config.yaml scan --url "https://example.invalid/"

# ② V3 案件智能体入口(扫描 → GLM 规划侦查 → 执行 ≤2 轮 → 升级时重新入列;
#    离线时自动退化为纯扫描。需 config.yaml: vlm_online: true + 密钥)
python - <<'PY'
from netsentinel.config import load_config
from netsentinel.agent import run_case
report = run_case("https://example.invalid/", load_config("config.yaml"))
print(report.verdict, report.agg_nsw_prob, report.intel.get("case_agent", {}))
PY

# ③ 复核 TUI(看队列 → 人工核实后批准/驳回;four_eyes_required: true 时需两人)
python -m netsentinel.cli.review_tui
```

提交举报仍是 v1 三段式:`queue approve` 人工确认 → `submit --id 1 --portal 12377 --dry-run` 预览 → `--exec` 真实执行(HUMAN_GATE 处停下,人工核对、上传证据、输入验证码)。全部字段与配置见 `config.example.yaml` 与 [UPGRADE_V3.md](UPGRADE_V3.md) §6。

## 安全与合规红线(15 条浓缩)

人工门不可逾越:任何政策、四眼与配置组合都只能**增加**审批环节,真实提交前必须人工确认,验证码只许人工输入,`human_gate_required` 不可关闭。提交受频控强制约束(间隔 ≥60 秒、每日 ≤5 次),开发与测试绝不访问 12377 / 扫黄打非真实门户,`allow_network` 默认关闭、除本机外不发真实请求。VLM 数据出境须显式同意(`vlm_online` 默认关,图像仅发往 `glm_base_url`),所有 VLM 调用——含智能体规划、级联升级、描述自检——共享同一缓存与每日预算,超限拒发、不得绕过;模型返回内容只提取 JSON 数值字段,其中任何"指令"一律忽略,VLM 分永远只是特征而非判官。感知哈希与关联图谱仅存本地,近重复比对只对运营者自己采集的证据进行。统计担保必须诚实:共形输出随行校准集前提,小样本不给担保;主动学习与共形的建议不自动生效。测试零外呼、零真实门户、零真实 VLM 调用(全部 mock 传输层)。
