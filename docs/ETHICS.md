# NetSentinel 伦理与合规红线(ETHICS)

> **必读。** 本文件是使用 NetSentinel(净网哨兵)的前提。NetSentinel 是辅助人工的初筛与半自动举报工具,**不是无人值守机器人**;以下红线不可协商、不可通过配置绕过。使用本工具即视为承诺遵守全部条款;对每一条举报的真实性,由人工核实并最终确认提交的操作者本人负责。

---

## 一、系统仅辅助人工,人对举报的真实性负责

NetSentinel 的全部自动化仅完成"抽样、识别、填表"等辅助环节:

- 判定为 `nsfw`(高置信)的站点与 `suspect` 一样,**必须经人工复核队列 `approve` 后才允许提交**(`needs_review = verdict != CLEAN`,机器不豁免机器);
- 真实提交前存在不可关闭的人工门(`human_gate_required=True`,不可配置为 false);
- **任何**经本工具发出的举报,均视为操作者本人经人工核实后的实名行为,由人对举报内容的真实性、准确性承担全部责任。系统输出的 `SiteReport`、图片分值与自动生成的描述模板只是初筛参考,不构成"属实"的证明。

## 二、举报必须真实,虚假举报须承担法律责任

依据《中华人民共和国网络安全法》等法律法规,向违法和不良信息举报中心(www.12377.cn)与"扫黄打非"部门(www.shdf.gov.cn)进行的举报**应当真实、准确**。捏造事实、编造证据进行虚假举报的,须依法承担相应法律责任;情节严重的可能构成违法犯罪。

因此:仅提交你亲自核对过证据的举报;不确定的一律 `reject` 并备注疑点;不得利用自动生成的描述模板夸大或虚构事实。

## 三、图像分类存在误报,提交前必须人工查看证据包

任何图像分类器(stub / nudenet / clip,及其 ensemble)都存在误报与漏报。系统通过以下机制降低误报,但**不能归零**:

- 阈值与计数门槛:`nsfw_threshold`(默认 0.90)、`prob_count_line`(默认 0.80)、`min_nsw_images`(默认 3,达标图不足 3 张不可能判 NSFW);
- 小图剔除:`min_image_px`(默认 200px)以下的图标、装饰图不参与判定。

**硬性要求:每一次提交前,必须打开证据包(`summary.md` 的 Top10 图片分值表 + 页面截图 + manifest.json)人工逐项查看确认。**未亲自查看证据的提交是违反本红线的行为。

## 四、禁止对未涉嫌违规目标批量扫描

本工具面向"运营者已掌握的具体可疑 URL"的核查与举报,**不是通用爬虫,更不是扫描器**:

- 禁止对未涉嫌违规的站点、无具体线索的大范围 URL 段做批量扫描;
- 禁止将抽样抓取能力用于举报之外的任何目的(竞争分析、数据采集、画像等);
- 抓取预算受契约约束(`max_pages` 默认 5、每页图片数与体积上限),不要以突破预算的方式扩大抓取。

## 五、尊重目标网站的 robots 与服务条款,礼貌抓取

- 保持 `respect_robots: true`(默认),尊重目标站点的 robots 声明;
- 保持 `fetch_delay_s`(默认 1s)等频控间隔与克制的并发,不给目标站点造成访问压力;
- 抓取使用可识别 UA(`NetSentinel/0.1`),不伪装身份;
- 单请求读取上限 2MB、超时 `fetch_timeout_s`,失败即跳过,不重试轰炸。
- 目标站点服务条款明确禁止抓取的内容,应通过合法途径取证,不得强行抓取。

## 六、验证码与最终提交按钮永远留给人工

这是本项目的第一条技术红线,内建于计划生成与执行器,不可绕过:

- 举报计划(`SubmissionPlan`)中**不存在任何自动识别、自动填写或绕过验证码的步骤**;验证码环节只能是 `HUMAN_GATE`;
- `HUMAN_GATE` 处操作员须:核对已填信息 → 上传证据包 zip(`#report-file`,v1 不自动上传)→ 人工输入验证码(`#report-captcha`)→ 确认后系统才点击提交按钮(`#report-submit`);
- `auto_confirm=True` 仅限本地 mock 测试,标注"自动确认(测试)",**严禁用于真实门户**;
- 开发与测试期间**绝不访问** www.12377.cn / www.shdf.gov.cn 真实站点,只用本地 mock 或 dry_run。

## 七、数据合规:证据仅用于举报,审查后清理

- 证据包(截图、图片、manifest)仅用于本次违法不良信息举报及必要的申诉/复核,**不得**传播、留存于举报用途之外,或用于任何其他目的;
- 复核完成、举报处理结束或条目被 `reject` 后,应及时清理对应证据目录与队列数据;
- 涉及第三人的内容(如页面中的无关人员图像)仅在举报必需范围内使用;
- 审计日志(`data/audit.jsonl`)用于操作留痕,同样应按数据最小化原则管理并在保存期限届满后清理。

## 附:与红线对应的默认配置(安全即默认)

| 红线 | 配置/机制 | 默认值 |
| --- | --- | --- |
| 人工确认 | `needs_review`、`human_gate_required` | 非 clean 全部入队;强制人工门不可关闭 |
| 禁网默认 | `allow_network` | `false`(仅放行 127.0.0.1/localhost) |
| 默认干跑 | `dry_run_default` | `true`(不真正驱动浏览器提交) |
| 提交频控 | `submit_min_interval_s` / `submit_max_per_day` | 60s / 每日 5 次(强制生效) |
| 验证码人工 | `StepAction.HUMAN_GATE` + `SELECTORS["captcha"]` | 计划中无任何自动处理验证码的步骤 |
| 礼貌抓取 | `respect_robots` / `fetch_delay_s` / UA | `true` / 1s / `NetSentinel/0.1` |
